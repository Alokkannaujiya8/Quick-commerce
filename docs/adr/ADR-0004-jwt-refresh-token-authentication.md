# ADR-0004: Dual-Token JWT & Cryptographic Rotating Refresh Tokens

## Status
Approved

## Context
QuickCart requires secure, stateless authentication for web and mobile clients that minimizes database lookup latency on high-frequency API calls while preserving immediate revocation control and multi-device session management.

## Decision
1. **Short-Lived Access Tokens**: Authenticated requests transmit an HMAC-SHA256 signed JWT with a 15-minute expiration (`Jwt:AccessTokenMinutes`), validated statelessly via ASP.NET Core `JwtBearer`.
2. **Rotating Refresh Tokens**: Sessions are sustained via 64-byte CSPRNG random tokens valid for 30 days (`Jwt:RefreshTokenDays`).
3. **Cryptographic Hash Storage**: The raw refresh token is **never stored** in the database. Only its SHA-256 digest (`TokenHash`) is stored in `identity.RefreshTokens`.
4. **Token Rotation & Revocation**: Every refresh operation revokes the previous token and generates a brand-new token pair. Explicit logout marks `RevokedAt = DateTime.UtcNow`.
5. **Password Security**: Passwords are saved exclusively as salted hashes generated by `BCrypt.Net-Next` (`EnhancedHashPassword`).

## Consequences
### Positive
* High-throughput API operations do not query the database to validate authentication.
* Storing only SHA-256 token hashes prevents token hijacking even if database backups are exposed.
* Refresh token rotation detects and prevents replay attacks.

### Negative / Trade-offs
* Clients must implement token refresh interceptors.
* Access tokens cannot be revoked before their 15-minute expiration without maintaining an in-memory blocklist.
